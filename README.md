# ⚔ WEST INDIA KOMBAT — Story Edition 3.0 · кампании + онлайн-кооператив

Браузерный пиксельный файтинг с 9 персонажами по фотографиям, 9 сюжетными кампаниями и 54 главами-испытаниями. Игра работает без сборки: **HTML + CSS + JavaScript**, GitHub Pages подходит.

## Как опубликовать на GitHub Pages

1. **Распакуй ZIP**. На компьютере должна появиться папка с `index.html`, `game.js`, `campaign.js`, `network.js`, `style.css`, `.nojekyll` и папкой `assets/`.
2. Создай **новый публичный репозиторий** на GitHub, например `west-india-kombat`.
3. Загрузи **содержимое** распакованной папки в корень репозитория. **Не загружай один ZIP**: GitHub Pages не распаковывает его при публикации.
4. Открой **Settings → Pages → Build and deployment**.
5. Выбери **Source: Deploy from a branch**, **Branch: main**, **Folder: /(root)** и нажми **Save**.
6. Открой адрес вида `https://ТВОЙ-НИК.github.io/west-india-kombat/` — фактическую ссылку GitHub покажет в **Settings → Pages**.

Важно: файл должен называться **`index.html`**, находиться на верхнем уровне папки Pages и иметь рядом папку `assets`.

## 📜 Сюжетная кампания каждого персонажа

1. Открой сайт, выбери своего бойца в сетке из 9 портретов.
2. В выпадающем **«Режим»** выбери **«📜 СЮЖЕТНАЯ КАМПАНИЯ»**.
3. Нажми **«НАЧАТЬ БОЙ»** — откроется история выбранного персонажа, список из шести глав и диалог перед сражением.
4. Выбери тактику: **«НАПОР»** (больше энергии и урона) или **«СТОЙКОСТЬ»** (больше здоровья). Нажми **«НАЧАТЬ ГЛАВУ»**.
5. Победи врага в **двух раундах**, чтобы открыть следующую главу. При поражении можно заново пройти текущую главу.
6. После шестой победы увидишь **уникальную концовку**. Можно переиграть главы или пройти историю другого персонажа.

У каждого из 9 бойцов своя сюжетная линия, свои 6 заголовков миссий, диалоги, враги и эпилог — **54 боя** при полном прохождении всех историй. Кампании одиночные: сетевые режимы расположены отдельно.

**Автосохранение:** игра сохраняет наибольшую пройденную главу для каждого бойца в локальном хранилище браузера (`localStorage`). Интернет для сюжетного режима **не нужен**, если файлы игры уже доступны. Прогресс **не синхронизируется между устройствами** и может исчезнуть при очистке данных сайта или открытии другого браузера.

Полные названия девяти кампаний перечислены в `CAMPAIGNS.md`.

## Как поиграть с другом

1. Первый игрок открывает опубликованную игру, выбирает бойца и нажимает **🌐 ИГРАТЬ ПО СЕТИ**.
2. Выбирает **1 на 1** или **Вместе против босса** и нажимает **СОЗДАТЬ КОМНАТУ**.
3. Копирует появившуюся ссылку и отправляет другу.
4. Друг открывает ссылку, выбирает своего бойца на экране выбора, снова открывает сетевое окно и нажимает **ПОДКЛЮЧИТЬСЯ**. На приглашённой странице код комнаты уже подставлен.
5. Хозяин видит статус «Друг подключился!» и нажимает **НАЧАТЬ БОЙ**. Если хочет сменить бойца, можно на время закрыть сетевое окно крестиком.

**Режимы:**
- **Онлайн 1 на 1**: каждый игрок управляет своим персонажем с другого устройства.
- **Онлайн кооператив**: оба игрока в одной команде против управляемого компьютером босса. Если погибнут оба игрока — поражение; если победят босса — общая победа.
- Офлайн-режимы **сюжетная кампания, против компьютера, локальный VS, турнир, выживание и тренировка** сохранены.

**Управление 1-го игрока**: A/D — ходьба, W — прыжок, S или удерживание ПКМ — блок, J или ЛКМ — удар, K — удар ногой, L — спецудар, I — тяжёлый, U — захват, Q — парирование, пробел — рывок.

**Второй игрок в онлайн-режиме** управляет у себя обычными кнопками первого игрока — WASD, ЛКМ, ПКМ и т. д. В локальном VS второй игрок использует стрелки и цифровые клавиши.

## Как устроено соединение

- Файл `game.js` содержит локальный движок игры.
- Файл `network.js` добавляет сетевой интерфейс, комнаты и протокол команд.
- Файл `campaign.js` хранит сюжетные линии и логику прохождения кампаний.
- **Хозяин (host)** вычисляет атаки, здоровье, состояние босса и правила победы. Гость отправляет кнопки и получает снимки состояния мира примерно 18 раз в секунду.
- Для установления WebRTC-соединения используется **PeerJS 1.5.5** и его публичный PeerJS Cloud. Библиотека загружается с `unpkg.com`; игровые состояния обычно передаются прямо между браузерами. Без доступного сервиса сигнализации создать сетевую комнату нельзя.
- GitHub Pages — только статический хостинг, он **не обеспечивает собственный сервер комнат**. Бесплатный облачный сервис PeerJS не гарантирует доступность и качество соединения. На некоторых сетях с жёстким NAT соединение может не установиться без TURN-сервера.
- **Интернет обязателен для мультиплеера**. При обычной игре против компьютера соединение не требуется (если все файлы уже сохранены).

Этот проект использует идеи проектирования сетевой синхронизации из [cranebeaker/coop-anything](https://github.com/cranebeaker/coop-anything), но **не выдаёт его инструменты разработки за готовый браузерный сетевой SDK**. Подробности — в `COOP_NOTES.md`.

## Важно про фотографии

При публикации **все фотографии персонажей станут доступны посетителям сайта и репозитория**. Публикуй их только с разрешения людей, изображённых на снимках.

## Проверки

Проверены: загрузка UI и 9 бойцов в Chromium, все 9 сюжетных кампаний по 6 глав, открытие следующих глав после двух побед, сохранение в имитированном `localStorage`, эпилоги, бой против компьютера и сетевое меню. Для сетевой части ранее проверялись начало кооперативной битвы с 3 участниками, протокол в локальной имитации «host + guest», передача ввода P2 и получение игровых снимков. **Реальная связь через публичный PeerJS Cloud с двух разных устройств пока не проверялась** — её нужно испытать после публикации.
